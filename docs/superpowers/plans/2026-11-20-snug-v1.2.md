# Snug v1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Snug reopens its main window where it was, remembers maximized windows, and keeps unsaved text across a crash, with v1.1 sessions upgrading cleanly.

**Architecture:** Rust owns session and draft files under the data folder. Window state is settled once at startup, before the main window is shown. The frontend writes a draft per dirty tab, debounced, and deletes only the drafts it wrote or restored. Confirmed discards delete drafts before the window closes.

**Tech Stack:** Tauri 2, Rust (serde, serde_json, dirs), TypeScript, React, Vitest.

**Spec:** [docs/superpowers/specs/2026-11-20-snug-v1.2-design.md](../specs/2026-11-20-snug-v1.2-design.md)

## Global Constraints

- Everything the design does not list keeps v1.1 behaviour, including tab drag, tear-off, and the quit prompt wording.
- Quitting with unsaved edits still asks first (design decision 1). Confirming discards the edits.
- Drafts are written while typing, debounced to about one second (1000 ms). Only a crash or forced shutdown brings them back.
- A draft that cannot be applied because the file changed on disk is kept aside as a readable `.md` in `drafts/`, and the notice shows its full path. Nothing is saved over the file automatically.
- Session and draft files live under `data_root()/Snug`, so `SNUG_DATA_DIR` moves them.
- Version 1.2.0 in `tauri.conf.json`, `package.json` and `Cargo.toml`. The installer is `Snug_1.2.0_x64-setup.exe`.
- Test builds use identifier `com.snug.test` and their own `SNUG_DATA_DIR`. Pass the `--config` JSON from a file, not inline (PowerShell 5.1 mangles the quotes).
- Before any real mouse or key input, check with WindowFromPoint that the target is a Snug window.
- Use the native dialogs from `lib/dialogs.ts`. Do not use `window.confirm`.
- No commits and no tags. SK commits on request.

## Review Focus

1. SK's real v1.1 `session.json` upgrades without losing the session or opening at the wrong size. The main window there is stored with maximized geometry (`x:-13, y:-13, 2880×1659`) as normal bounds. → Task 1, `v11_maximized_geometry_upgrades_to_maximized`.
2. One tab's draft is never deleted or overwritten by another instance, or by a clean instance of the same note. → Task 5, `a_clean_instance_leaves_an_existing_draft_alone`.
3. A draft is never applied over a file that changed on disk without a notice. → Task 5, `a_draft_for_a_changed_file_is_kept_aside_and_reported`.
4. A confirmed discard does not come back after a relaunch, even when a debounced write is pending. → Task 5, `a_discarded_draft_is_not_written_again`.
5. A saved position off-screen (monitor unplugged) still comes back on screen for the main window. → Task 3, `fit_saved_brings_an_off_screen_window_back`.

### Task 5: Frontend draft behaviour in `useDocument`

**Files:**
- Modify: `src/hooks/useDocument.ts`
- Modify: `tests/useDocument.test.ts` (new cases; existing cases unchanged)

**Interfaces:**
- Consumes: the four Task 4 commands.
- Produces:
  - `export interface Draft { path: string; text: string; base_modified: number }`
  - `export interface DraftIo { read(path): Promise<Draft | null>; write(path, text, baseModified): Promise<void>; remove(path): Promise<void>; keepAside(path): Promise<string> }`
  - `export const noDraftIo: DraftIo`: read gives `null`, the rest resolve. Used by default and in the browser preview.
  - `export const tauriDraftIo: DraftIo`: wraps the four commands.
  - `export function discardDraft(path: string, drafts: DraftIo = tauriDraftIo): Promise<void>`: adds the path to a module-level discarded set (this stops a pending debounced write for that path). Removes the draft only if this window owns it. `ownedDrafts`, a module-level set, gets the path when this window writes or restores a draft, and loses it when the draft is removed. A window never removes a draft it does not own (Review Focus 2).
  - Invoke arguments are camelCase in JS (`baseModified`), as `write_markdown` takes `expectedModified`.
  - `useDocument(initialPath, io = tauriDocumentIo, drafts: DraftIo = noDraftIo)`. `UseDocument` gains `notice: string | null`.
- Behaviour rules:
  1. On load, read the draft before any write or remove. Clear the path from the discarded set.
  2. Draft present and `base_modified === loaded.modified`: its text becomes `source`, the file text stays `saved`, and this instance owns the draft.
  3. Draft present and the modified time differs: `keepAside`, `notice` = `Unsaved text from before the file changed on disk was kept in <full path>.`, and the instance does not own a draft.
  4. Dirty and not discarded: write after 1000 ms of quiet, with `base_modified = current.modified`. Each change restarts the timer. The write is skipped if the path is in the discarded set.
  5. Owned and clean (`source === saved`): remove the draft, and stop owning it. This covers save and exit-with-discard.
  6. An instance that never read or wrote a draft never removes one.
