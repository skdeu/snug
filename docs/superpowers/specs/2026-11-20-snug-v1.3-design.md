# Design: Snug v1.3 — glass look and UI/UX pass

Date: 2026-11-20
Status: direction chosen by SK on 2026-11-20 (in-app glass, Graphite and sage). Not built yet. The plan waits for SK's go.
Visual reference: canvas artboard "Dark glass, library open" (private design canvas, not published)

## Intent and the why

Snug looks flat: solid panels, rectangular tabs, buttons made of translucent boxes. SK wants a modern look with glass, dark and light. Reading comfort stays the product. v1.3 changes how Snug looks and how its controls read. It does not change what Snug does.

## Goals

- Window chrome (tab strip, toolbar, sidebar, find bar, notices) sits on glass: translucent panels blurred over an ambient backdrop that Snug paints itself.
- Graphite and sage is the default palette, in dark and light. The toolbar offers four more.
- One token layer for colours, surfaces, radii, type and focus. Today the same `rgba(127, 127, 160, …)` values repeat across the CSS files.
- Clear control states: hover, pressed, focus-visible, active tab, selected file, and the Library toggle shows whether it is open.
- Icons: inline SVG replaces the text glyphs (▤ ☾ ☀ ⌕ ✎ ×). Labels stay.
- The reader and the editor get a designed theme: tables, footnotes, task-list boxes, code and links in both themes, and a real CodeMirror theme with syntax colours.
- Notices become cards with a visible dismiss button. Click-to-dismiss stays.
- Version 1.3.0 everywhere, and the README matches the app.

## Non-goals

- No Windows-drawn backdrop (Mica, Acrylic or Blur) and no transparent window. The window stays opaque, so the look is the same on Windows 10 and 11, and no window setting changes.
- No new features: no search across notes, no pinned tabs, no tab-drag changes.
- The app offers the five palettes from the toolbar, saved as a `palette` setting. Graphite and sage is the default.
- No custom title bar (`decorations: false`). The native title bar stays. A custom one would touch the drag regions and the tab tear-off that v1.1 and v1.2 verified.
- Native confirmation dialogs (`askYesNo`) are not restyled. Windows draws them.
- No cloud, sync, or telemetry.

## Anti-goals

- Reading comfort is not traded for looks. The reader column and the editor stay nearly opaque.
- No text below 4.5:1 contrast on its surface, counting the glass layers beneath it.
- No blur behind the reader or the editor, and no animated backdrop.
- Upgrading from v1.2 must not change `session.json` or `settings.json`.
- Tab drag, tear-off, keyboard shortcuts and the quit prompt keep their v1.2 behaviour.

## Constraints

- Runs on Windows 10 and 11 with WebView2 (the README already says Windows 10 needs the WebView2 runtime).
- CSS `backdrop-filter` only. Tauri and window configuration are not touched beyond the version number.
- Keep the Rust and TypeScript split as it is.
- Keep the class names that code and tests depend on: `.snug-reader`, `.snug-tab`, `.snug-tabbar`, `.snug-error`, `theme-dark`, `theme-light`.
- Test builds use `com.snug.test` and their own `SNUG_DATA_DIR`, as before.
- Starts from the uncommitted v1.2 working tree. v1.2 is not committed yet.

## Decisions (made by SK, 2026-11-20)

1. **Glass is drawn by Snug.** The alternative was Windows' own backdrop (Mica). SK chose the in-app glass, so it looks the same on every Windows version.
2. **Palette: Graphite and sage is the default.** SK kept all five palettes available in the app (2026-11-20), so the toolbar picker offers them, saved as the `palette` setting.

## Glass in the app

- The window's root paints an ambient backdrop: two soft blobs on the palette's ground. Dark: `#2e4f3c` and `#1d3f47` on `#14171a`. Light: `#cfe3d3` and `#d6e6e0` on `#eef1ee`. It is painted once and never animates.
- Chrome panels (tab strip, toolbar, sidebar, find bar, notices) sit on `backdrop-filter: blur(24px) saturate(150%)` over the glass fill. Only chrome uses backdrop-filter. The reader and the editor do not.
- Glass fill: dark `rgba(20, 23, 26, 0.58)`, light `rgba(238, 241, 238, 0.66)`.
- The reader column has its own near-opaque ground, so long reading sits on a calm surface, not on the blobs.
- The canvas artboard shows a floating window inset from its edges. The real window is full size, so the blobs show behind the chrome and the sidebar, not around a frame.
- Fallback: when `backdrop-filter` is not supported (`@supports not (backdrop-filter: blur(1px))`), chrome uses the solid glass tokens and the ambient backdrop is not painted. Where the reduced-transparency preference is available to the webview, it also selects the solid look.

### Contrast, computed

Solid pairs (reader and editor):
- Dark: text 14.8, muted 8.3, accent 9.5, error 8.7.
- Light: text 13.9, muted 6.3, accent 5.6, error 5.9.

Glass chrome, over the lighter of the two ambient blobs (the worst case, since the glass sits over both):
- Dark: text 11.6 on glass, 7.2 on the active tab. Muted 6.5 on glass, but **4.0 on the active tab, which fails**.
- Light: text 13.2 on glass, 10.9 on the active tab. Muted 6.0 on glass, 5.0 on the active tab.

Rule: active tab, selected file and notice text use `--text`, never `--text-muted`. Dark muted fails on the accent-soft surface.

## Surfaces (the complete list)

Every item below gets its states (default, hover, pressed, focus-visible, disabled where it applies) in both themes and on the solid fallback.

- **Window ground:** `--bg-solid` with the ambient blobs painted on top. Solid fallback: `--bg-solid` alone.
- **Tab strip:** glass strip, inactive tab, active tab (accent top edge, `--accent-soft`), hover, dragging (existing opacity 0.6), dirty dot (●) in accent, close × shown on hover and focus, `+ Open note`.
- **Toolbar:** one grouped bar: Library (shows `aria-pressed` and an active look while the sidebar is open), Light/Dark theme toggle, Open, Edit, and Save in edit mode.
- **Find bar:** glass input, focus ring, Enter and Esc behaviour unchanged.
- **Sidebar:** glass ground, `Open folder…`, search input with a search icon, `MY NOTES` label, file items (default, hover, selected, focus; long names ellipsised).
- **Reader:** ground, headings, paragraphs, links, blockquote, inline code, code blocks, tables (borders and header row), images (radius), horizontal rules, footnotes (`markdown-it-footnote`), task-list checkboxes (`markdown-it-task-lists`, accent-coloured), selection colour, and a meta line under the title.
- **Editor:** a CodeMirror theme (ground, gutter, cursor, selection, active line) and a highlight style for headings, emphasis, links, code and quotes. The highlight style needs `@codemirror/language`, already installed as a dependency of `@codemirror/lang-markdown`, so it is added to `package.json` explicitly.
- **Editor status line:** `● Unsaved` and `Saved`, Save button, hint text.
- **Notices:** error notices (`.snug-error`) use `--error` text on a card with an `--error` border. Info notices (for example "This file changed on disk") use `--accent-soft` with an accent icon. Both have a × dismiss button. Click-to-dismiss stays.
- **Empty state:** `No note open.` with its two buttons.
- **Scrollbars and form controls:** `color-scheme` set per theme.
- **Icons:** one small `Icon` component (`src/components/Icon.tsx`), hand-drawn SVG paths, `aria-hidden` when a text label sits beside it. No new icon package.
- **Accessibility:** tabs get `role="tab"` and `aria-selected`. Pointer handling is unchanged. No arrow-key tab navigation in v1.3.

## Risks

- `backdrop-filter` costs GPU time while resizing. Blur only the fixed chrome (tab strip, toolbar, sidebar, find bar). Never blur the reader. Watch resize on the 2880×1800 screen.
- Blur only sees what is behind it. The tab strip sits above the reader, so no note text passes under the glass.
- The canvas floats the window inside its artboard, so it shows more blob than the real window will. Check the real app before deciding how strong the blobs are.
- In-app glass can be captured by PrintWindow, which makes screenshot checks possible. Confirm this on the first run; if the capture is blank, fall back to manual checks.

## Tests

- Vitest:
  - token pairs meet 4.5:1 on the solid grounds;
  - the glass composites meet 4.5:1 for text and muted text on glass, and for text on the active tab, using the blending formula and the ambient colours above;
  - no literal `rgba(127, 127, 160` outside `tokens.css`;
  - the active tab rules do not set `--text-muted`;
  - `chrome.css` has the `@supports not (backdrop-filter …)` fallback;
  - `backdrop-filter` appears only in `glass.css`, on chrome selectors, and not in the reader or editor CSS;
  - `Icon` renders `aria-hidden` SVG;
  - tabs have `role="tab"` and `aria-selected`;
  - the Library toggle has `aria-pressed`;
  - a notice's dismiss button clears it.
- Baselines: Vitest 66 plus the new tests, `tsc --noEmit` clean, cargo test as in v1.2.
- Manual, SK at the screen, on a `com.snug.test` build: the glass in dark and light; the theme toggle; the tab strip and sidebar at full width; a torn-off window; a real-mouse drag; a restart keeps place and size; resize stays smooth.
- The solid fallback is checked by the CSS test and by reading, not by a live run. A live run would need a dev-only switch, which this version does not add.
