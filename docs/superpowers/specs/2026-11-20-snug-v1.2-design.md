# Design: Snug v1.2 — windows and unsaved text that come back

Date: 2026-11-20
Status: approved by SK on 2026-11-20. Nothing is built yet.

## Intent and the why

v1.1 works, but after a restart the main window ignores where it was and always opens maximized, and text that was typed but not saved is lost. v1.2 makes the window state and the unsaved text behave the way SK expects from a browser: what was open, where, and how big comes back, and nothing typed is silently lost.

## Goals

- The main window comes back in the place and size it was left, the same as the other windows.
- A window that was maximized opens maximized, and un-maximizing it returns to its last normal size.
- Unsaved text per tab survives a crash or forced shutdown, and comes back on the next launch, marked as unsaved.
- Version 1.2.0 everywhere, and the README matches what the app does.

## Non-goals

- No new features beyond the above: no search across notes, themes, pinned tabs, or tab-drag changes.
- No cloud, sync, or telemetry.

## Anti-goals

- Upgrading from v1.1 must not wipe SK's saved session.
- Unsaved text must never be discarded without SK saying so.
- A restored draft must never overwrite a file that changed on disk.

## Constraints

- Keep the Rust and TypeScript split as it is (`session.rs`, `windows.rs`, `commands.rs`, `App.tsx`, `useDocument.ts`).
- Session and draft files live under the data folder that `settings.rs` already resolves, so the `SNUG_DATA_DIR` override applies to them too.
- Test builds use a different identifier and their own `SNUG_DATA_DIR`, as before.

## Decisions (made by SK)

1. **Quitting with unsaved edits still asks first.** SK chose "Still ask" on 2026-11-20. Closing a window, or a tab, with unsaved edits keeps the current prompt. Confirming discards the edits. Cancelling keeps the window open. No silent keeping on a normal close.

## My calls (SK to confirm)

These were not settled in the conversation. I chose them to fit decision 1.

2. **Drafts are written while typing, so only a crash or forced shutdown brings them back.** Each dirty tab's text is written to `drafts/` under the data folder, one file per note, named from a hash of the note's path. Writes are debounced to about one second and use the existing atomic write. A draft is deleted when the note is saved, and when SK confirms a discard.
3. **Restoring a draft at launch.** A draft that survives a launch is loaded into its tab and shown as unsaved. It is restored only if the note's modified time on disk still matches the time the draft recorded. If the file changed, the draft is kept aside and the tab shows a notice that the file changed on disk. Nothing is saved over the file automatically.
4. **Main window placement.** Remove `maximized: true` from `tauri.conf.json`. The main window is created hidden, placed from the saved session, then shown, so it does not flash. With no saved session (first run), it opens maximized.
5. **Maximized state is remembered without losing the normal size.** `SavedWindow` gets a `maximized` field with `#[serde(default)]`, so a v1.1 `session.json` still loads. While a window is maximized, only the flag is updated and the last normal bounds are kept. Applies to note windows too.
6. **Version 1.2.0** in `tauri.conf.json`, `package.json` and `Cargo.toml`, so the installer name changes to `Snug_1.2.0_x64-setup.exe`. The README's install path, size, and feature list are updated to match.

## Tests

- Rust: a v1.1-shaped `session.json` loads with every window's tabs and bounds. A window saved while maximized keeps its normal bounds. A draft round-trips, and a draft is refused when the file's modified time has changed.
- Frontend: a dirty tab writes a draft after the debounce. Save and confirmed discard delete it. A restored draft shows as unsaved. The changed-on-disk notice appears when the file changed.
- Existing suites keep passing: vitest (50), `tsc --noEmit`, cargo test (29).
- Manual, with SK present: a real-mouse drag out of a window, confirming the main window's position and maximized state come back after a restart, and a crash test with unsaved text on a test build.

## Left to the builder

- Exact draft file format and debounce length, within the constraints above.
- The order of hide, place, and show for the main window, provided it does not flash.
- Names of the new functions and tests.
